# Multi-window and desktop experience

Support independent portfolio documents and deliberate additional views of the
same portfolio. Editable comparison windows should share the portfolio connection,
not require separate read-only connections.

## Tasks

| Task | Status |
| --- | --- |
| Provide launcher and portfolio windows with native menus | ✓ |
| Resolve portfolio commands through the invoking window | ✓ |
| Forward second-instance file requests using the sender's working directory | ✓ |
| Focus an existing window for an ordinarily reopened file | ✓ |
| Add deliberate New Window with shared connection ownership | ○ |
| Keep each window's filters, selection, and destination independent | ○ |
| Refresh affected windows after mutations | ○ |
| Persist recent files and handle missing files clearly | ○ |
| Add and verify custom keyboard shortcuts | ○ |
| Translate remaining menu and dialog strings | ○ |
| Consider menu icons as a nice-to-have | ○ |
| Handle macOS file-open events and verify menu switching | ○ |
| Smoke-test packaged cold/warm file opening on supported desktop platforms | ○ |
| Verify independent state across different portfolio documents | ○ |

## Notes

The earlier multi-second native file-dialog delay disappeared after a restart.
It is not an outstanding portfolio-load optimization task.

## Open decisions

- Cross-window invalidation and refresh behavior after edits.
- Initial destination and selection state of a new comparison window.
