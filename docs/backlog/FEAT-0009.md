# Multi-window and desktop experience

Support independent portfolio documents and deliberate additional views of the
same portfolio. Editable comparison windows should share the portfolio connection,
not require separate read-only connections.

## Notes

The earlier multi-second native file-dialog delay disappeared after a restart.
It is not an outstanding portfolio-load optimization task.

## Navigation state and menu gating

First iteration: menu items stay enabled; a screen registers its own
selection-gated handler (for example Edit Account in the accounts list), so the
item does nothing elsewhere. Introduce Rust-held per-window state (route and
selection, keyed by window label, apply on focus) when the first screen needs
real disabling or eligibility must be shared with context menus and double click.

## Database events

Publish change events from the data layer after committed mutations so every
window of the same portfolio can refresh. Pairs with the shared-connection New
Window task. Decide event granularity (table, entity, or row) and delivery to
windows.

## Open decisions

- Whether Rust mirrors React selection eagerly or derives enabled flags only.
- Re-sending state after a webview reload.
- Cross-window invalidation and refresh behavior after edits.
- Initial destination and selection state of a new comparison window.
