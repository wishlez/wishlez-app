# Technical debt and reliability

Track concrete internal cleanup, defensive handling, and regression prevention.
Keep user-facing capabilities in their owning features. This is a rolling bucket;
its status reflects recorded work, not a promise to eliminate all technical debt.

## Tasks

| Task | Status |
| --- | --- |
| Separate application callbacks, window orchestration, state, and data modules | ✓ |
| Move the shared error type out of the former utility folder | ✓ |
| Encapsulate portfolio registry access and launcher-reopen atomic state | ✓ |
| Remove the redundant portfolio-path lookup wrapper | ✓ |
| Stabilize frontend menu-event handlers and subscription cleanup | ✓ |
| Remove obsolete menu debug output | ✓ |
| Surface or log currently discarded asynchronous window errors | ○ |
| Verify initial active-window tracking and handle stale menu targets if needed | ○ |
| Guard New against replacing an already-open file as a nice-to-have | ○ |

## Open decisions

  a clear already-open error.
- Which external-open failures need user-visible feedback in addition to logging.
