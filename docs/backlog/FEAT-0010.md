# Technical debt and reliability

its status reflects recorded work, not a promise to eliminate all technical debt.

## Logging task scope

- Silent errors: replace discarded results in second-instance handling, Dock
  reopening, launcher reopening after exit requests, and the Open Launcher menu
  action with explicit error reporting. Preserve non-panicking menu-switch error
  handling and surface actionable failures in the UI where appropriate.
- Production diagnostics: configure persistent file logging, for example with
  `tauri-plugin-log` targeting the app's per-user log directory. Capture the above
  errors and existing menu-switch diagnostics even when launched from Finder or
  the Dock, rather than relying on terminal-only `eprintln!` output. Document how
  users can locate and share logs for debugging.

## Open decisions

- Whether New targeting an open file should focus its existing window or return
  a clear already-open error.
- Which external-open failures need user-visible feedback in addition to logging.
